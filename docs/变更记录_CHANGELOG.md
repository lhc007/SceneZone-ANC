### [2026-09-18] 在线 Ŝ 辨识默认关闭：无辅助噪声时其稳态解是 Ŝ≡0
- **状态**: 已提交 78e2962
- **基线**: cb907cc
- **变更代码**:
  - 修改: `include/scenezone_types.h` — `GFANC_CONFIG_DEFAULT` 的 `sec_online_mu`
    由 `5e-6f` 改为 `0.0f`；字段注释写明"非 0 会静默关掉 ANC，仅供复现故障"
  - 修改: `src/sec_online.c` — 文件头注重写为新结论 + 推导（原"dither 会平均掉"论断作废）
  - 修改: `main_realtime.c` — 启动横幅改印 `Online Ŝ: OFF (2026-09-18 定案…)`；
    `GFANC_SEC_MU > 0` 时另往 stderr 打警告（含 τ≈1/(2µ) 的秒数估算）
- **变更原因**: 真机单变量 A/B（同一 exe，只改 `GFANC_SEC_MU`，90s adapt）：

  | µ | NR | ch1（误差麦） |
  |---|---|---|
  | `5e-6` | 峰值 9.2 → 末段 **0.1** | 0.10 → 回到无控基线 0.25~0.27 |
  | `0` | 稳定 **9.2~12.8** | 稳在 0.11~0.18（≈6dB 实测降噪） |

  存入库槽的 Wc RMS 也从 0.010/0.016 变回 0.017/0.021（µ=5e-6 存的是个 −3.4dB 缩水成品）。
  机理（NLMS 稳态残差与激励正交）：
  `(Ŝ−S)⊛R_aa = R_da`；近完美对消时 `S⊛anti ≈ −d ⟹ R_da ≈ −S⊛R_aa ⟹ Ŝ⊛R_aa = 0`。
  **对消越好，Ŝ 越趋近 0；不动点在 0，与步长无关。** 故这不是调参问题。
- **造成影响**:
  - 行为: **默认行为变了** —— 默认配置下不再跑在线 Ŝ 辨识。旧默认的后果链是
    Ŝ↓ → Fx_arr↓ → 梯度饿死 → 只剩 leak 衰减 Wc → Wc→0 → 输出归零，
    而保护栈全是"太响"型判据（safety_mute / peak_mute / P0-4），
    **没有任何一条能看见"静默自关"这条路径**。
  - 配置: `GFANC_SEC_MU` 仍在，但非 0 **仅用于复现故障**，不可用于标定。
  - 性能/内存: 默认路径省掉 `sec_online_init` 与每样本 NLMS 更新，算力下降。
  - 未验证项: **辅助噪声注入版本没做**（教科书在线 SPM 的做法：注入 probe 并从 err
    中减去其对消分量）。所以"在线辨识"能力当前等于不可用，不是被修好了。
- **验证方式**: 上述单变量 A/B；`mingw32-make realtime` 后在启动横幅确认印 `Online Ŝ: OFF`。
- **回退方式**: `GFANC_SEC_MU=5e-6` 恢复旧行为（会复现静默自关；启动时会打警告）。

### [2026-09-18] 诊断：三路 16k WAV 原样转储 (GFANC_DUMP_REF)
- **状态**: 已提交 78e2962
- **基线**: cb907cc
- **变更代码**:
  - 修改: `include/scenezone_types.h` — 新增 `dump_prefix[96]` 字段 + `GFANC_DUMP_REF` 解析

- **变更原因**: 唯一的频谱读数 = howling 检测的 anti 监视，只覆盖 bin 8..24 =
  [500, 1500]Hz，看不到 1750/2250/3250Hz 等更高次谐波，而"滋滋"的刺耳感多半来自那些。
  已确证的只有"750Hz（250Hz 的三次谐波）是一条相干谱线且发生在数字链路之后"
  （Wc 在 750Hz 只有 −67dB → 不是 DSP 造的）。"是放音喇叭失真还是 ANC 喇叭失真"
  无法从现有日志分离，于是把三路原样落盘：`.ref`（参考麦，未过 mic 增益/AGC/反馈抵消）、
  `.err`（误差麦 ch1）、`.anti`（实际送 DAC 的反噪，out_gain/ramp 之后）。
- **造成影响**:
  - 行为: 不设 `GFANC_DUMP_REF` 时零行为变化（只多一次 `g_dump_on` 分支）。
  - 配置: 新增 `GFANC_DUMP_REF=<前缀>`，空串 = 关。
  - 性能/内存: **回调里写盘，非实时安全**（诊断专用）。开启时每样本 2 次 `fputc`。
  - 未验证项: 三路文件之间的时间对齐（同一次运行同一批样本，理论上相位对齐）
    没做交叉验证。
- **踩坑记录（重要）**: WAV 头的**定期回填必须放音频回调线程**。放主线程时，
  主线程的 `fflush/ftell/fseek` 与回调的 `fputc` 竞争同一个 `FILE*` 的读写位置 →
  每秒丢 1~2 个样本，int16 流错位，落盘文件比头里声明的短（实测 ref −6 / err −2 /
  anti −5 字节）。更糟的是丢样本产生的阶跃是宽频点击，幅度恰好落在 −50~−60dB ——
  正是要看的谐波梯子所在的量级，会污染读数。放回调里就只剩单线程碰文件；
  主线程只在流停止后（`cleanup`）调 `dump_wav_close`，那时回调已停，不构成竞争。
- **验证方式**: 设 `GFANC_DUMP_REF` 跑一段，退出时打印各文件样本数；
  强杀（`Stop-Process -Force`）下最坏丢 1 秒，而不是丢整个文件。
- **回退方式**: 不设该 env 即完全关闭。

**64 帧缓冲实验（已否决，全部回退）**

| 请求缓冲 | 实测环路延迟 | 子窗聚类 | 滑移 |
|---|---|---|---|
| 128 帧 | 200 样本 = 12.50ms | 17/17 全聚 | 0ppm |
| 64 帧 | 146 样本 = **9.12ms** | 17/17 全聚 | 0ppm |
| 32 帧 | 136 样本 = **8.50ms** | 17/17 全聚 | −16ppm |

- **收益非线性，地板 ~8.5ms**：128→64 省 3.38ms，64→32 只再省 0.62ms。
  声学飞行只占 0.62ms（Ŝ 峰位），其余 ~7.9ms 是驱动/USB 内部缓冲，**代码动不了**。
- 64 帧下重标 `band_0` 进槽 6：首轮触发 **6 次 `Wc rescued`**。根因是
  `diverge_anti_rms=0.25` **照 128 帧工作点定的**（128 帧时 anti 仅 0.08–0.11，离阈值差一倍多，
  保护根本没机会触发），64 帧下 anti 0.28–0.42 一越线就被**误判发散、回滚重爬**。
  把 `GFANC_DIVERGE_ANTI=0.6` 后 → **0 次**。
- 但开 `GFANC_WCET=1` 量到 **决定性数据**：

  | 模式 | WCET 中位 | WCET 最大 | 64 帧预算 1333µs |
  |---|---|---|---|
  | **标定 (adapt)** | 1154 µs | **1741 µs** | **超 27/116 窗口 (23%)** |
  | **部署 (fixed)** | **228 µs** | **574 µs** | **0/90，富余 2.3×** |

  **标定路径在 64 帧下不满足实时性**（中位已吃 87% 预算，尖峰越线 31%）→ ASIO 丢缓冲
  → 自适应被喂进断掉的数据。**部署路径反而便宜 5 倍，完全跑得动**。
  即：不是「机器扛不住小缓冲」，是「**标定**扛不住」。
- 该 64 帧滤波器的 A/B：**+0.63 dB（更差）**，但只有 9 组配对、效应 ≈1.2 标准误，且
  **丢缓冲对 ON 不对称**（OFF 输出全零，丢缓冲无害；ON 丢缓冲 = 往反噪声里插不连续 →
  宽带噪声灌进误差麦），系统性把结果往"更差"推。**判为不可解释，不作"滤波器坏"的结论。**
  另一次 64 帧 A/B 为 −0.41dB —— 两次骑在 0 上，同样放 `band_0` 而 128 帧的槽 0 是 −3.15dB。
- **结论**：延迟越小越好在物理上成立，但**这台机器上标定路径算力不够**。已全部回退到 128 帧。

### [2026-08-08] 设计决策留档 — tanh 增益域 vs 论文 [0,1] 非负权重 / CNN 路径解耦（均暂不改）

- **留档 1 — tanh [-1,1] 带符号增益 vs 论文 [0,1] 非负权重**:
  - 现状: `scene_ctrl_process` 对 CNN logits 做 `tanh` → 每扬声器每子带增益 ∈ [-1,1]（带符号，允许相位翻转），`Wc=Σ gain×sub` 后 RMS 标定 + 取反

  - 权衡: 带符号增益表达力强（可反相、逐扬声器独立），但标签求解域更宽 → CNN 回归更难、训练数据需求更大；[0,1] 非负更易学、有界更稳，但表达受限（只能幅度组合）

- **留档 2 — CNN 与路径解耦（论文 §2.2: 新声学环境只重训子滤波器, CNN 直接迁移）**:
  - 分析结论: 当前标签由真实 MIMO 路径批量 LMS 求解（路径相关）。解耦 = 合成路径（带通）上求标签 → CNN 只学"噪声频谱 → 子带组合"，与路径无关
  - **为什么暂不改**: ① 当前单窗口固定声学环境，真实路径标签严格更优（初始 Wc 更准），解耦在本机不会提高降噪量、反而会略降初始质量；② 收益仅在**多窗型产品**（每台窗型=新路径，免重训 CNN）；③ 需重训 + 硬件 A/B
  - 触发条件（满足再实施）: 出现第二套窗型/开窗姿态需部署；或 CNN 迁移性测试失败
- **回退方式**: 无代码变更，仅文档
