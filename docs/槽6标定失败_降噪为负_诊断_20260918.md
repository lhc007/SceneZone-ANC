# 槽 6 标定失败：deploy 下误差麦被反向放大 4.3dB

> **目的**: 记录 2026-09-18 实测确认的故障 —— deploy 加载槽 6 后误差麦**不降反升**，
> 以及顺着这条线查出的收敛判据缺陷（`NR` 是模型自评，可与真麦克风**反向**）。
>
> **证据纪律** (本文档强制):
> - **【实测】** = 本机跑出来的数字，附命令 / 文件 / 样本数
> - **【代码】** = 可直接 grep 到的 `file:line`
> - **【未证】** = 只是候选解释，**没有任何一次实验支持**，不许当结论用

日期: 2026-09-18
基线: `cb907cc` + 工作区未提交改动
exe: `scenezone_realtime.exe` mtime 2026-09-18 12:55 (`mingw32-make realtime`)
硬件: 输入/输出设备均为 ASIO **23 = UMC ASIO Driver** (in=4 out=4 fs=44100)
噪声: 外部设备循环播放 `data/synth_noise/band_6.wav`（**不是** ANC 自己那路喇叭）

---

## 0. 一句话

槽 6 标定"成功"（exe 报 `NR` 涨到 6.5dB、判收敛、存库）是**假成功**：
它存下的滤波器在 1215Hz 处是一根 **Q≈104、带宽 11.7Hz** 的细谐振器，
拿去消 478Hz 宽的 band_6 —— 只在 11.7Hz 那一条上可能有用，其余频率相位全错，
净效果是把误差麦**放大 4.3dB**。exe 的 `NR` 之所以没发现，是因为它算的是
**模型**反噪声 `Wc ⊗ Ŝ ⊗ ref`，不是麦克风测到的东西。

## 2. 直接原因：槽 6 的 s1 是一根 Q≈104 的细谐振器

直接量库文件（`data/wc_bank.bin`，7 槽，slot_len=2048 = S(2)×L(1024)，
槽 6 数据起点 = 16 + 6×2048×4 = 49168）：

```python
import numpy as np, struct
d = open('data/wc_bank.bin','rb').read()
magic, ver, nslots, slen = struct.unpack_from('<4I', d, 0)   # 16B 头: magic+ver+count+指纹
w = np.frombuffer(d, dtype='<f4', count=slen, offset=16+6*slen*4).reshape(2, 1024)
H = np.fft.rfft(w[1], 8192); f = np.fft.rfftfreq(8192, 1/16000.)
# → |H| 峰 21.44 @ 1215Hz, −3dB 带宽 11.7Hz
```

| 通道 | 带内 max \|H\| | 峰频率 | −3dB 带宽 | Q |
|---|---|---|---|---|
| s0 | 3.11 | 1053 Hz | 217 Hz | ≈5 |
| **s1** | **21.44** | **1215 Hz** | **11.7 Hz** | **≈104** |

**算术：** band_6 = 963–1441Hz，宽 **478Hz**。用 11.7Hz 宽的响应去覆盖 478Hz 宽的激励，
只有 2.4% 的频段有可能对消，剩下 97.6% 的频率上这个滤波器照样在输出、
但相位是错的 ⇒ 净效果是加分。实测 +4.3dB 与此一致。

**这笔账也解释了 `HW: anti f=1188Hz peak=9–10dB`：** 用 `howling_detect` 的
精确参数（`HW_FFT_N=256`、`HW_MIN_BIN=8`、`HW_MAX_BIN=24`、`HW_EDGE_GUARD=2`，
bin 宽 62.5Hz）算过：**bin 居中的单音，峰/均值 = 1.5/17 → 10.5dB**。
实测 8.4–10.1dB ⇒ **那个 anti 信号本来就是一根接近单音的东西**（带噪声被 Q=104 的
谐振器整形后的结果），不是带噪声。

**检测器为什么不报警：** `HW_ANTI_THRESH_DB = 12.0f`
（`include/howling_detect.h:50`）> 实测 10.1dB ⇒ `notches=0`。
软膝点 0.9 也只在 0.21% 的样本上被碰到 ⇒ `peak_mute` 不触发（阈值 0.99）。

## 3. 为什么 exe 会报"收敛" —— `NR` 是模型自评

### 3.1 代码【代码】

```c
/* main_realtime.c:718-729 */
float pa    = ctx->acc_anti_est;
float cross = ctx->acc_err_cross;
float pd    = pe + pa - 2.0f * cross;          /* d = err - anti_est */
ctx->nr_level = 10.0f * log10f((pd + 1e-12f) / (pe + 1e-12f));
```

`anti_est` 是 **`Wc ⊗ Ŝ ⊗ ref` 的模型输出**，不是麦克风测到的反噪声
（由 `acc_anti_est` 累加，`main_realtime.c:686` 起，且被 `!anc_fixed()` 门控 ——
所以 deploy 下 `antiEst=0.0000` 是预期的）。

而存库的收敛判据用的就是这个数：

```c
/* main_realtime.c:1115-1124 */
int saved = sm_check_convergence(
    ctx->nr_level, cfg.nr_converge_db, ...);   /* ← 判据是 nr_level */
```

**⇒ `NR` 度量的是"模型认为自己对消了多少"，不是"麦克风听到降了多少"。
只要 Ŝ 与真实次级路径不符，`anti_est` 就是错的，`NR` 可以和真实残差反向。exe 在给自己打分。**

### 3.2 铁证：槽 6 那次标定，`NR` 和真麦克风方向相反【实测】

把那次 adapt 运行每秒的 `[ANC] NR=` 和 `raw: ... ch1=` 对齐：

| anti | NR（exe 说） | ch1（真误差麦） | ch1/ch0 |
|---|---|---|---|
| 0.0004 | 0.0 dB | 0.1106 | 2.62 |
| 0.0028 | 0.1 dB | 0.1158 | 2.75 |
| 0.0068 | 0.2 dB | 0.1269 | 3.02 |
| 0.0102 | 0.4 dB | 0.1185 | 2.78 |
| 0.0147 | 0.7 dB | 0.1222 | 2.90 |
| 0.0315 | 1.0 dB | 0.2024 | 4.74 |
| 0.0463 | 1.9 dB | 0.1522 | 3.66 |
| 0.0890 | 4.4 dB | 0.1499 | 3.55 |
| 0.1327 | 5.4 dB | 0.1805 | 4.28 |
| 0.1964 | **6.5 dB** ← 它在这判"收敛"并存库 | 0.2014 | 4.81 |
| 0.2103 | 5.8 dB | 0.2103 | 5.02 |

`ch0` 全程 0.0416–0.0428（音源稳定）。

```
anti:    0.0004 → 0.2103   (+54 dB)
NR:         0.0  → 6.5 dB  (exe 认为在越来越接近收敛)
ch1:     0.1106 → 0.2103   (+5.6 dB 更吵)
```

**同一次运行、同一秒，`NR` 上涨而误差麦同步变吵。** 之后 exe 打印
`[SAVE] 已保存标定滤波器 (收敛快照) → 库 data/wc_bank.bin 槽6 (OK)` 并自退。

### 3.3 对照组：同一次会话里另一个槽是**真降下来了**【实测】

| anti | NR | ch1 | ch1/ch0 |
|---|---|---|---|
| 0.0268 | 0.4 dB | 0.3547 | 7.40 |
| 0.2887 | 14.6 dB | 0.2004 | 4.17 |
| 0.4253 | **26.0 dB** | 0.0870 | 1.79 |
| 0.4543 | **29.4 dB** | **0.0420** | **0.87** |

那次 `ch1` 0.3547 → 0.039 ≈ **−19 dB**，`NR=29.4dB` 也同意。
**⇒ 算法本身能work，不是全局坏掉，是槽 6 这一次没work。**

## 4. 判据替换：看 `ch1/ch0`，别看 `NR`，也别只看 `anti`

| | 健康那次 | 槽 6 那次 |
|---|---|---|
| `NR` 终值 | 29.4 dB | 6.5 dB |
| `anti` 终值 | 0.454 | 0.196 |
| **`ch1/ch0`** | **7.40 → 0.81（一路降，−19dB）** | **2.62 → 5.02（一路涨，+5.6dB）** |

**新判据：** 标定过程中盯每一行 `[ANC]` 的 `raw: ch1=` 和 `ch0(ref)=`，
算 `ch1/ch0`。**只要它不降反升，立刻 Ctrl+C，不要等它报"收敛"。**
用 `ch0` 做分母，能把音源/音量的漂移约掉 —— 这也是为什么它比 `ch1` 绝对值可靠。

## 5. 整库体检：不只是槽 6 【实测】

`data/wc_bank.bin` 全部 7 槽，逐槽在自己频带内的响应（8192 点 FFT）：

| 槽 | 频带(Hz) | s0 带内max \|H\| | s0 峰Hz | s0 Q | s1 带内max \|H\| | s1 峰Hz | s1 Q |
|---|---|---|---|---|---|---|---|
| 0 | 56–80 | **0.10** | 102 | 1 | **0.35** | 102 | 2 |
| 1 | 89–126 | 3.05 | 133 | 3 | 1.83 | 82 | 8 |
| 2 | 135–209 | 5.63 | 184 | 3 | 2.43 | 238 | 2 |
| 3 | 223–344 | 6.03 | **250** | **21** | 9.33 | **250** | **21** |
| 4 | 362–543 | 3.44 | 408 | 1 | 4.51 | 352 | 11 |
| 5 | 585–894 | 6.39 | 748 | 8 | 6.58 | 656 | 4 |
| 6 | 963–1441 | 3.11 | 1053 | 5 | **21.44** | **1215** | **104** |

频带边缘取自对 `data/synth_noise/band_k.wav` 的实测。

两个额外发现：

1. **槽 0 基本是空的。** 带内 max \|H\| = 0.10（s0）/ 0.35（s1），比最弱的还低 ~20dB；
   而且它的峰值落在 **102Hz —— 在 band_1(89–126) 里，不在自己的带里**。
2. **槽 3 是 250Hz 处 Q=21 的细谐振。** 这正是 2026-09-16 那次**纯音标定**留下的形状，
   与既有的"单音探针会落进 band 解的凹陷"是同一个坑。

**⇒ "标定收敛到细谐振器"看起来是个模式，不是槽 6 的偶发。** 但**为什么会这样，未证**（见 §7.2）。

## 6. 顺带查出的两个次要缺陷

### 6.1 `bandpass_anc.bin` 的上沿切掉了 band_6 的顶部 【实测】

`data/bandpass_anc.bin`（头 `0x434E4647` ver 1 count **64** fp `0xdb382ff9`，272 字节），
64 抽头，群延迟平坦 **1.97ms**（与代码注释"群延迟 2ms"一致）：

| 频率 | \|H\| |
|---|---|
| 250 Hz | 0.907 |
| 500 Hz | 0.994 |
| 700 Hz | 0.999 |
| 1000 Hz | 0.998 |
| 1200 Hz | 0.955 |
| 1250 Hz | 0.917 |
| 1400 Hz | 0.703 |
| **1441 Hz** | **0.622** |

**−3dB 通带上沿 = 1396 Hz。** 而 band_6 = 963–**1441**Hz ⇒
**7 个 band 里只有 band_6 跑出了这个带通**，上沿 45Hz 处在 −4.1dB 的滚降里。

> 注意不要过度解读：band_6 中心 1202Hz 处 \|H\|=0.955，几乎没损失；
> 而 deploy 实测那根线在 1215Hz。**所以这一条解释不了 +4.3dB**，
> 它只是 band_6 特有的一个待办。

### 6.2 三路转储**没有记录闯祸的那个通道** 【代码】

```c
/* main_realtime.c:786-788 —— 只推 ch0 */
dump_push(0, ctx->ref_buf[n]);
dump_push(1, ctx->err_buf[n*E+0]);
dump_push(2, anti_spk[0]);        /* ← 只有 s0 */
```

而槽 6 的细谐振在 **s1**（`anti_spk[1]`），**根本没被转储**。
所以拿现有 `GFANC_DUMP_REF` 去量"实测 anti→err 传递函数 vs 库里的 Ŝ"是量不准的 ——
量到的是那个"形状正常"的 s0。

### 6.3 exe 自己标出的一条不一致【实测】

```
Loop delay auto-loaded: 200 (12ms), dsp_delay=190
Ŝ model delay = 12.50ms (dsp_delay=190 + peak@10), 期望环路≈4-6ms
```

`data/secondary_path.bin` 的 6 条路径峰都在 tap 10–12（0.62–0.75ms），
代码却按 **12.50ms** 建模。这是 Fx 里的一个纯相位误差。
**但早先扫过延迟、曲线是平的，所以不许拿它当差异的解释。**

## 7. 待验证 / 下一步

### 7.1 通道隔离 A/B（库已生成，等一次运行）

为了在不改代码、不重编 exe 的前提下看清 **是 s0 还是 s1 在闯祸**，
已从 `data/wc_bank.bin` 拆出两个新库（**只新增文件，原库未动**）：

- `data/wc_bank_slot6_s0only.bin` —— 槽 6 只留 s0（s1 全零）
- `data/wc_bank_slot6_s1only.bin` —— 槽 6 只留 s1（s0 全零）

两次都跑 deploy + 外部循环播 `data/synth_noise/band_6.wav`（同一音量），
读稳定后的 `ch1`，与基线 0.1177 比：

| A(s0only) | B(s1only) | 结论 |
|---|---|---|
| ≈0.118 | ≈0.19 | s1 是全部原因 → 只需修槽 6 的标定 |
| ≈0.19 | ≈0.118 | 是 s0（形状正常但相位错）→ 查增益/延时 |
| 都 ≈0.118 | 都 ≈0.118 | 单通道都不吵、合起来吵 → 是两通道互相抵消，问题在标定本身 |

### 7.2 为什么标定会收敛到细谐振器 —— 三个候选，**均未证**

1. **Fx 的相位错**（`Fx = bp_fx(Ŝ ⊗ ref_anc)`，`main_realtime.c:489-500`）。
   Ŝ 相位一错，FxLMS 下降的就不是真实代价，只在"Fx 相位刚好合适"的那一个频率上有效
   ⇒ 解会长成单频 —— 与观察到的形状吻合。**但 §6.3 那条延迟线索早先扫过是平的。**
2. **`leak` 把工作点钉住**：`anti_rms > 0.18` 时 `leak` 连续 ×1→×10
   （`main_realtime.c:527-530`），而槽 6 的 `anti` 恰好**park 在 0.18–0.21**，
   长时间贴着这个阈值的上沿。**巧合，还是有因果，没查。**
3. **band_6 顶部被带通切掉**（§6.1）。band_6 是唯一跑出带通的 band，
   与"只有槽 6 长成这样"吻合，但解释不了 1215Hz（带内 \|H\| 0.955）。

### 7.3 建议但**尚未做**的代码改动

- **加一路 `anti_spk[1]` 转储**（`<前缀>.anti2.wav`），否则 §6.2 那个盲区一直在。
- **把收敛判据从 `nr_level` 换成基于 `ch1/ch0`（真实残差）的量**，
  或至少在 `ch1/ch0` 上升时拒绝存库。这是本次最该修的一条：
  现在的判据会把"反向放大"判成"收敛"。

> 两处都等确认，未动代码。

## 8. 本次被推翻的旧结论（必须记住）

| 旧说法 | 本次实测 |
|---|---|
| "判标定成败看 `anti`：`anti` 涨到 ~0.10 稳住 = 成功" | **错。** 槽 6 的 `anti` 涨到 0.21，是真失败（+5.6dB 更吵）。`anti` 只说明"输出涨到工作点了"，不说明相位对不对。 |
| "`NR` 单次运行内能漂 5.8dB，所以不可作判据" | **理由说轻了。** `NR` 不只是"漂"，它是**模型自评**，可以系统性地与真实残差**反向**（§3）。 |
| "exe 打印 `[SAVE] 已保存标定滤波器 (收敛快照)` = 标定成功" | **不成立。** 那次 `[SAVE]` 是真的执行了，存下的是 Q=104 的谐振器。 |
| "槽 6 是空的（anti≈1e-4）" | 已修：重标后 `anti` 涨到 0.19，但**方向和相位不对** —— 从"不干活"变成"干反活"。 |
